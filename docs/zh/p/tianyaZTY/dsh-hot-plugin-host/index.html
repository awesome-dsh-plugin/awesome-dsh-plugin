README

DeepSeek Harness 运行时插件加载——不再需要重启。

DSH 的 loader 树在启动时组合，所以新增一个静态客户端插件（UI 面板、小组件、看板）通常必须重启 dsh web。这个插件解决它：监视一个热目录，在运行中把客户端插件 bundle 安装/更新到所有打开的页面。

写一个 bundle → ~/.dsh/hot-plugins/<id>/client.js
      ↓（宿主每 1.5s 扫描）
/hot-plugins/list + SSE 事件 + bundle 服务
      ↓（浏览器半端）
拉取 → __ModuleLoader__.load 注册 → loader.create（完整 cordis fiber 生命周期）
      ↓
插件在所有打开页面即时上线——无重启、无需刷新

更新同理（覆盖文件 → invalidate + 就地刷新）。删除目录 → 下次页面加载后插件消失。

安装

# 在本仓库目录下
mkdir -p ~/.dsh/profiles/web/node_modules
ln -s "$PWD" ~/.dsh/profiles/web/node_modules/dsh-hot-plugin-host
# 在 ~/.dsh/profiles/web/package.json 的 dsh.profile.bundles 追加：
# "dsh-hot-plugin-host"

然后重启一次 dsh web（宿主本身是启动插件）。从此以后，所有新插件都走热目录，零重启。

npm：dsh-hot-plugin-host（发布后可用）

用法

把 bundle 丢进热目录：

mkdir -p ~/.dsh/hot-plugins/my-widget
cp examples/demo-widget/client.js ~/.dsh/hot-plugins/my-widget/
# 约 1.5s 内，所有打开的页面即时生效

热 bundle 与启动 bundle 是相同的 __ModuleLoader__.load 格式：

window.__ModuleLoader__.load({
  id: "my-widget",                       // 必须等于目录名
  factory: (require) => {
    // require 仅限客户端模块表闭集：react、react/jsx-runtime、
    // @deepseek-ai/dsh-client-runtime/client 等
    const inject = ["sessions", "slots", "locale"];
    function apply(ctx) { /* 完整插件能力：ctx.slots.register(...) */ }
    exports.apply = apply;
    exports.inject = inject;
    return module.exports;
  }
});
  • id：[A-Za-z0-9@._-]，单段，不含 /
  • 路由：GET /hot-plugins/list、GET /hot-plugins/events（SSE）、GET /hot-plugins/<id>/client.js
  • 热目录：环境变量 DSH_HOT_PLUGINS 覆盖，默认 ~/.dsh/hot-plugins（自动创建）

示例

示例 说明
packages/dsh-client-ui-subagent-dashboard 右侧列子智能体看板：实时状态、可展开详情、后台任务、一键打开子代理会话记录。独立 npm 包；也可作为热 bundle 使用。
examples/demo-widget 最小自包含热 bundle：实时状态胶囊。

安全

热目录是信任边界，与启动 bundles 等价（热插件拥有完整客户端服务访问权）。仅限本机开发环境——绝不要放入不可信内容。

原理

  • 宿主半端（lib/index.js）：在 ctx.webServer 注册 /hot-plugins 路由（清单/SSE/bundle），轮询热目录（mtime+size → rev），广播 change 事件。
  • 浏览器半端（lib/client.js）：注入 loader；连接时对账（list），订阅 SSE，拉取变更 bundle，经标准模块加载器执行，再以 loader.create 挂载——与官方 dsh-cordis-client-runner 挂载动态包完全相同的机制，热插件获得完整 fiber 生命周期（激活门控、effect 清理、状态投影）。
